What you are building

The correct category and name

Standard description

An internal business development (BD) lifecycle platform for a security services contractor: capture management, proposal management and bid pricing, with win/loss and competitive intelligence, plus post-award contract administration.

Technically it is a modular monolith web app (Next.js on Vercel) on a single system of record (Supabase Postgres + Storage). A Python worker service handles documents and web acquisition. A human-in-the-loop document pipeline turns files into verified records. A remote MCP server gives AI agents the same tools the UI uses.

Naming corrections
ProductContract Intelligence Platform. "Contract intelligence" is an industry term for AI analysis of signed contracts (a CLM add-on). That's only your post-award module. UseCapture & proposal platform or BD platform; keep "contract administration" for the post-award module. Data lifecycle

How a file becomes trusted data

This is a staged (medallion-style) pipeline with a human-in-the-loop gate. AI and parsers only ever write to staging; a person promotes facts into the canonical records.

SOURCEAcquireUpload, Drive import, public portal crawl or records request.
RAW · BRONZEPreserve originalExact copy in the vault with checksum and version. Never overwritten.
STAGING · SILVERParse & extractText, tables and fact candidates with confidence and page/cell locators.
HUMAN GATEVerify & reconcileReviewer accepts, corrects, rejects or flags conflicts. The workflow waits here.
CANONICAL · GOLDPromoteAudited function writes the verified value into business tables.
SERVINGUseRetrieval index, metrics, reports, proposal drafting, MCP tools.
